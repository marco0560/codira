# C++ native source-call qualification — 2026-10-20

## Shared comparison gap

The broad 650-original measurement exposed large member/operator and macro/implicit-call comparison holds. These were not hundreds of established analyzer defects: the old oracle compared native AST operations with lexical source calls without representing their different inventories.

`cpp_native_call_sites_r2.py` projects explicit native calls onto physical source callee sites independently of the analyzer. Simple dot and arrow member calls use the field name's physical position and retain receiver, target and logical external name. Native member access must agree with the written access operator. Implicit conversion and assignment operations are retained separately, and their explicit nested argument calls remain traversed. An explicit operator-function spelling is held rather than discarded.

A namespace macro may project its source beginning only when the native spelling comes from the command-line/built-in origin, the exact command supplies a simple object replacement, and the source contains the namespace qualifier followed by a physical callee ending. A source redefinition or whole function-like macro expansion cannot satisfy this proof. Duplicate native AST occurrences at one physical lexical site are recorded separately from the source-site inventory; different physical sites remain distinct. Complex or unmapped callees remain holds.
